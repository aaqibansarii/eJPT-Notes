## Linux Vulnerabilities
### Frequently Exploited Linux Services
Linux is a free and open source operating system that is comprised of the Linux kernel, which was developed by Linus Torvalds, and the GNU toolkit, which is a collection of software and utilities that was started and developed by Richard Stallman.

This combination of open source software is what makes up the Linux OS as a whole, and it is
commonly referred to as GNU/Linux.

Linux has various use cases, however, it is typically deployed as a server operating system. For this reason, there are specific services and protocols that will typically be found running on a Linux server.

These services provide an attacker with an access vector that they can utilize to gain access to a target host.

Having a good understanding of what these services are, how they work and their potential
vulnerabilities is a vitally important skill to have as a penetration tester.

| Protocol/Service        | Ports              | Purpose                                                                                                                                                     |
|-------------------------|--------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Apache Web Server       | TCP ports 80/443   | Free and open source cross-platform web server released under the Apache License 2.0, Apache accounts for over of web servers globally.                    |

### Bash CVE-2014-6271 Vulnerability (Shellshock)
Shellshock (CVE-2014-6271) is the name given to a family of vulnerabilities in the Bash shell (since V 1.3) that allow an attacker to execute remote arbitrary commands via Bash, consequently allowing the attacker to obtain remote access to the target system via a reverse shell.

The Shellshock vulnerability was discovered by Stéphane Chazelas on the 12th
of September 2014 and was made public on the 24th of September 2014.

Bash is a *Nix shell that is part of the GNU project and is the default shell for
most Linux distributions.

**CVE-2014-6271 - Shellshock**
The Shellshock vulnerability is caused by a vulnerability in Bash, whereby Bash mistakenly executes trailing commands after a series of characters: () {:;};.

This vulnerability only affects Linux as Windows does not use utilize Bash as it is not a *Nix based operating system.

In the context of remote exploitation, Apache web servers configured to run CGI
scripts or .sh scripts are also vulnerable to this attack.

CGI (Common Gateway Interface) scripts are used by Apache to execute
arbitrary commands on the Linux system, after which the output is displayed to
the client.

In order to exploit this vulnerability, you will need to locate an input vector or script that allows you to communicate with Bash.

In the context of an Apache web server, we can utilize any legitimate CGI scripts accessible on the web server.

Whenever a CGI script is executed, the web server will initiate a new process and run the CGI script with Bash.

This vulnerability can be exploited both manually and automatically with the use of an MSF exploit module.

### FTP (File Transfer Protocol)
FTP (File Transfer Protocol) is a protocol that uses TCP port 21 and is used to facilitate file sharing between a server and client/clients.

It is also frequently used as a means of transferring files to and from the directory of a web server.

FTP authentication requires a username and password combination. As a result, we can perform a brute-force attack on the FTP server in order to identify legitimate credentials.

In some cases, FTP servers may be configured to allow anonymous access, which consequently allows anyone to access to the FTP server without providing any legitimate credentials.

### SSH(Secure Shell)
SSH (Secure Shell) is a remote administration protocol that offers encryption and is the successor to Telnet.

It is typically used for remote access to servers and systems.

SSH uses TCP port 22 by default, however, like other services, it can be configured to use any other open TCP port.
SSH authentication can be configured in two ways:
- Username & password authentication
- Key based authentication


In the case of username and password authentication, we can perform a brute-force attack on
the SSH server in order to identify legitimate credentials and consequently gain access to the
target system.

### SAMBA
SMB (Server Message Block) is a network file sharing protocol that is used to facilitate the sharing of files and peripherals between computers on a local network (LAN).

SMB uses port 445 (TCP). However, originally, SMB ran on top of NetBIOS using port 139.

Samba is the Linux implementation of SMB, and allows Windows systems to access Linux shares and devices.

| Protocol/Service       | Ports            | Purpose                                                                                          |
|------------------------|------------------|--------------------------------------------------------------------------------------------------|
| Apache Web Server      | TCP ports 80/443 | Free and open source cross-platform web server released under the Apache License 2.0. Apache accounts for over 80% of web servers globally. |
| SSH (Secure Shell)     | TCP port 22      | SSH is a cryptographic remote access protocol used to remotely access and control systems over an unsecured network. SSH was developed as a secure successor to Telnet. |
| FTP (File Transfer Protocol) | TCP port 21 | FTP is a protocol that uses TCP port 21 and is used to facilitate file sharing between a server and client/clients and vice versa. |
| SAMBA                  | TCP port 445     | Samba is the Linux implementation of SMB, allowing Windows systems to access Linux shares and devices. |


**SAMBA Authentication and Enumeration**

SAMBA utilizes username and password authentication to gain access to the server or a network share. 

 **Brute-Force Attack on SAMBA**

We can perform a brute-force attack on the SAMBA server to obtain legitimate credentials. Once we have these credentials, we can use various tools to interact with the SAMBA shares.

**Tools for SAMBA Interaction**

**SMBMap**
- **Description**: After obtaining legitimate credentials, we can use a utility called **SMBMap** to enumerate SAMBA share drives.
- **Capabilities**:
  - List the contents of the shares.
  - Download files from the shares.
  - Execute remote commands on the target.

**smbclient**
- **Description**: **smbclient** is a client that is part of the SAMBA software suite. It communicates with a LAN Manager server and offers an interface similar to that of the FTP program.
- **Capabilities**:
  - Download files from the server to the local machine.
  - Upload files from the local machine to the server.
  - Retrieve directory information from the server.

**Conclusion**
Using these tools, we can effectively interact with SAMBA shares and perform various operations once we have obtained valid credentials.

### Misconfigured Cron Jobs
- **Linux implements task scheduling** through a utility called Cron.
- **Cron is a time-based service** that runs applications, scripts, and other commands repeatedly on a specified schedule.
- An application or script configured to run repeatedly with Cron is known as a **Cron job**.
- **Cron can automate or repeat** a wide variety of functions on a system, such as daily backups and system upgrades.
- The **crontab file** is a configuration file used by the Cron utility to store and track created Cron jobs.


- **Exploiting Misconfigured Cron Jobs**: Cron jobs can be run as any user on the system, making it crucial to monitor those configured to run as the "root" user.
- **Targeting Root Cron Jobs**: Cron jobs running as the root user can execute scripts or commands with root privileges, potentially granting unauthorized access.
- **Privilege Escalation**: To elevate privileges, it is essential to find and identify Cron jobs scheduled by the root user or the files being processed by these Cron jobs.

### SUID Binaries
- **SUID (Set Owner User ID)**: Specialized permission in Linux.
- **Function**: Allows execution of a script/binary with the owner's permissions.
- **Usage**: Enables unprivileged users to run specific scripts/binaries with **root** permissions.
- **Limitations**:
    - Grants temporary elevated privileges for execution only.
    - Misconfigurations or vulnerabilities can be exploited to gain elevated access.


- **Exploitation Goal**: Attempt to exploit SUID functionality to elevate privileges.
- **Factors for Success**:
    - **Owner of the SUID Binary**: Target SUID binaries owned by the **"root"** user or other privileged users.
    - **Access Permissions**: Ensure executable permissions are granted to execute the SUID binary.

## Linux Credential Dumping
### Linux Password Hashes
- **Multi-User Support**: Linux allows multiple users to access the system simultaneously, which can increase security risks by providing multiple access points for attackers.
- **User Information Storage**: All account information is stored in the `/etc/passwd` file, which is readable by all users.
- **Password Security**: User passwords are not stored in the `/etc/passwd` file; instead, they are encrypted and stored in the `/etc/shadow` file.
- **Access Control**: The `/etc/shadow` file can only be accessed by the **root** account, enhancing security by preventing unauthorized access to hashed passwords.


- The **`/etc/passwd`** file provides information about the hashing algorithm used and the password hash.
- The number following the username, enclosed by dollar signs (`$`), indicates the hashing algorithm and its strength:
    - **`$1`**: MD5
    - **`$2`**: Blowfish
    - **`$5`**: SHA-256
    - **`$6`**: SHA-512
