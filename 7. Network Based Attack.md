## Networking
### Networking Fundamentals

- **Network Protocols**: In computer networks, hosts communicate using network protocols, which enable different systems with varying hardware and software to interact.
- **Diversity of Protocols**: There are numerous network protocols designed for various services and functionalities.
- **Packet Communication**: Communication between hosts is facilitated through the transfer of data in packets, which encapsulate the information being sent.
----


- **Packets**: The primary goal of networking is to exchange information between networked computers, which is accomplished through packets.
- **Definition**: Packets are streams of bits transmitted as electrical signals over physical media (e.g., Ethernet, Wi-Fi).
- **Data Representation**: These electrical signals are interpreted as bits (zeros and ones) that constitute the information being communicated.
----

- **OSI Model**: The OSI (Open Systems Interconnection) model is a conceptual framework that standardizes the functions of telecommunications and computing systems into seven abstraction layers.
- **Purpose**: Developed by the International Organization for Standardization (ISO), it facilitates communication between different systems and devices, ensuring interoperability across various networking technologies.
- **Layers**: The OSI model consists of seven layers, each representing a specific functionality in the network communication process.

### SMB & NetBIOS Enumeration
NetBIOS and SMB are two different technologies, but they're related in the context of networking and file sharing on Windows networks.

**NetBIOS (Network Basic Input/Output System)**

- **Definition:**
    
    - An API and set of network protocols for communication services over a local network.
    - Primarily enables applications on different computers to find and interact with each other.
- **Primary Functions:**
    
    1. **Name Service (NetBIOS-NS):**
        - Allows computers to register, unregister, and resolve names in a local network.
    2. **Datagram Service (NetBIOS-DGM):**
        - Supports connectionless communication and broadcasting.
    3. **Session Service (NetBIOS-SSN):**
        - Supports connection-oriented communication for reliable data transfers.
- **Ports Used:**
    
    - **Port 137:** Name Service (UDP)
    - **Port 138:** Datagram Service (UDP)
    - **Port 139:** Session Service (TCP)



**SMB (Server Message Block)**
- **Definition:**
  - A network file sharing protocol that enables computers on a network to share files, printers, and other resources.
  - The primary protocol used in Windows networks for file and resource sharing.

- **Functions:**
  - File and printer sharing
  - Named pipes
  - Inter-process communication (IPC)
  - Allows remote file access as if they were local.

- **Versions:**
  - **SMB 1.0:** 
    - Original version with security vulnerabilities.
    - Used with older operating systems like Windows XP.
  - **SMB 2.0/2.1:** 
    - Introduced with Windows Vista/Windows Server 2008.
    - Improved performance and security.
  - **SMB 3.0+:** 
    - Introduced with Windows 8/Windows Server 2012.
    - Added features like encryption, multichannel support, and virtualization improvements.

- **Ports Used:**
  - **Port 445:** Direct SMB traffic (bypassing NetBIOS).
  - **Port 139:** SMB traffic when operating with NetBIOS.

**Relationship Between NetBIOS and SMB**

- **Historical Context:**
    
    - NetBIOS and SMB were once closely linked in network file and printer sharing.
- **Current Usage:**
    
    - Modern networks primarily rely on SMB for file and printer sharing.
    - DNS and other mechanisms are often used for name resolution instead of NetBIOS.
- **Modern Implementations:**
    
    - Current Windows implementations primarily use SMB and can function without NetBIOS.
    - NetBIOS over TCP (port 139) is still required for backward compatibility.
    - NetBIOS and SMB are often enabled together in modern systems.

### SNMP Enumeration
- **Definition:**
    
    - SNMP (Simple Network Management Protocol) is a widely used protocol for monitoring and managing networked devices.
- **Commonly Managed Devices:**
    
    - Routers
    - Switches
    - Printers
    - Servers
    - Other networked devices
- **Key Functions:**
    
    - **Querying Devices:** Allows network administrators to request status information from devices.
    - **Configuration:** Enables configuration of certain settings on network devices.
    - **Alerts/Traps:** Provides notifications when

----

- **Protocol Layer:**
    
    - SNMP operates at the application layer and typically uses UDP for transport.
- **Primary Components:**
    
    1. **SNMP Manager:**
        - The system responsible for querying and interacting with SNMP agents on networked devices.
    2. **SNMP Agent:**
        - Software running on networked devices that responds to SNMP queries and sends traps (notifications).
    3. **Management Information Base (MIB):**
        - A hierarchical database that defines the structure of data available through SNMP.
        - Each piece of data in the MIB has a unique Object Identifier (OID) for identification.

----
**Versions of SNMP (Simple Network Management Protocol)**

- **SNMPv1:**
    
    - The earliest version.
    - Uses community strings (essentially passwords) for authentication.
- **SNMPv2c:**
    
    - An improved version that supports bulk transfers.
    - Still relies on community strings for authentication.
- **SNMPv3:**
    
    - Introduced enhanced security features.
    - Includes encryption, message integrity, and user-based authentication.

**Ports Used by SNMP**

- **Port 161 (UDP):**
    
    - Used for SNMP queries.
- **Port 162 (UDP):**
    - Used for SNMP traps (notifications).


----
SNMP enumeration involves querying SNMP-enabled devices to gather information that can help identify potential vulnerabilities, misconfigurations, or points of attack.

**Key Objectives and Outcomes:**

1. **Identify SNMP-Enabled Devices:**
    
    - Determine which devices on the network have SNMP enabled.
    - Assess their vulnerability to information leakage or attacks.
2. **Extract System Information:**
    
    - Collect data such as device names, operating systems, software versions, and network interfaces.
3. **Identify SNMP Community Strings:**
    
    - Test for default or weak community strings that may grant unauthorized access to device information.
4. **Retrieve Network Configurations:**
    
    - Gather information about routing tables, network interfaces, IP addresses, and other network-specific details.
5. **Collect User and Group Information:**
    
    - In some cases, SNMP can reveal user account information and access permissions.
6. **Identify Services and Applications:**
    
    - Discover which services and applications are running on the target devices, potentially leading to further attack vectors.

### SMB Relay Attack
- **Definition**: An SMB relay attack intercepts and relays SMB traffic to gain unauthorized access to resources in Windows networks.
    
- **Process**:
    
    1. **Interception**: Attacker positions themselves between client and server (e.g., ARP spoofing).
    2. **Traffic Manipulation**: Intercepts authentication credentials (e.g., NTLM hashes).
    3. **Relaying**: Sends intercepted credentials to the legitimate server.
    4. **Unauthorized Access**: Gains access to resources as if they were the legitimate user.
- **Implications**:
    
    - Unauthorized access to sensitive data.
    - Lateral movement within the network.
    - Risks to data integrity.
    - Potential denial of service.
- **Mitigation Strategies**:
    
    - Enable SMB signing.
    - Disable NTLM authentication.
    - Implement network segmentation.
    - Use strong authentication (e.g., MFA).
    - Conduct regular security audits.
    - Monitor network traffic for anomalies.

----
 **How SMB Relay Attacks Work**

1. **Interception**:
    
    - The attacker establishes a man-in-the-middle position between the client and server using techniques like ARP spoofing, DNS poisoning, or by setting up a rogue SMB server.
2. **Capturing Authentication**:
    
    - When the client connects to the legitimate server via SMB, it sends authentication data (e.g., NTLM hashes). The attacker captures this data.
3. **Relaying to a Legitimate Server**:
    
    - Instead of decrypting the captured NTLM hash, the attacker relays it to another server that trusts the source, allowing them to impersonate the user.
4. **Gain Access**:
    
    - If the relay is successful, the attacker gains access to the server's resources, which may include sensitive files, databases, or administrative privileges, enabling further lateral movement within the network and compromising additional systems.
