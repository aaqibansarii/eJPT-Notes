## Network Mapping
**Definition**:  
The process of discovering and visualizing devices and connections in a network.

#### Key Points:

1. **Purpose**:
    
    - Understand network structure and identify vulnerabilities.
2. **Methods**:
    
    - **Active Scanning**: Using tools like Nmap.
    - **Passive Scanning**: Monitoring traffic.
    - **Manual Mapping**: Documenting existing setups.
3. **Tools**:
    
    - **Nmap**: For scanning.
    - **Wireshark**: For traffic analysis.
    - **Mapping Software**: e.g., SolarWinds, Visio.
4. **Output**:
    
    - Visual representation of the network and a list of devices.
5. **Benefits**:
    
    - Improves security and aids in troubleshooting.

```bash
########### CONSIDERATION ##########

# ICMP Ping:
Pros: ICMP ping is a widely supported and quick method for identifying live hosts.
Cons: Some hosts or firewalls may be configured to block ICMP traffic,
limiting its effectiveness. ICMP ping can also be easily detected.

# TCP SYN Ping:
Pros: TCP SYN ping is stealthier than ICMP and may bypass firewalls that allow outbound connections.
Cons: Some hosts may not respond to TCP SYN requests, and the results
can be affected by firewalls and security devices.
```

## Host Discovery with nmap
```bash
# always include -sn in host discovery otherwise nmap will scan ports
# scan the range of ips 0/24, 0-100, 0-254 etc
> nmap -sn 198.162.75.0/24
> nmap -sn 198.162.75.0-100
> nmap -sL ip # to list the ips we have in a ip range 10.10.10.10/27

# Scan multiple ips
nmap -sn 198.162.75.15 10.10.10.10 8.8.8.8
# scan from files
> nmap -sn -iL targets.txt
```

The command `nmap -sn 110.10.22.0/24 --send-ip` performs a ping scan on the subnet `110.10.22.0/24` to identify active hosts without scanning ports.

- **nmap**: Network scanning tool.
- **-sn**: Ping scan to check which hosts are up.
- **110.10.22.0/24**: Target subnet.
- **--send-ip**: Sends IP packets directly.

Packet Types Sent:

1. **ICMP Echo Requests**: To check host responsiveness.
2. **ARP Requests**: For local network discovery.
3. **TCP SYN Packets** (optional): To probe common ports.
4. **UDP Packets** (optional): To check specific ports.
```bash
> nmap -sn 110.10.22.0/24 --send-ip # performs a ping scan on the subnet  `110.10.22.0` to `110.10.22.255`
```

**Sending SYN packet (most prefered)**
```bash
> nmap -sn -PS <ip> # -PS sending SYN packet to host discovery 
							    # skipping -sn port scan

> nmap -sn -PS1-1000 <ip> # sending pkt to port 1-1000. 
> nmap -sn -PS3389 <ip># sending pkt to port 3389(RDP)
> nmap -sn -PS80,443,3389 <ip> # sending pkt to multiple ports 
```

**Sending ACK packets to target ip.**
```bash
# will send a packet with ACK flag set 
# if host is offline it will not respnd
# if host is online it will respond with RST as there was no proper 3 way hand shake


> nmap -sn -PA <ip> # sending ACK packet
> nmap -sn -PA1-1000 <ip> # sending pkt to the range of port 1-1000. 
> nmap -sn -PA3389 <ip> # sending pkt to specific port 3389 RDP
> nmap -sn -PA80,443,3389 <ip> # sca multiple ports 
```

**ICMP specific ping scan:**
```bash
> nmap -sn -PE <ip> # sending ICMP pkt

# sometimes on local eth0 it above does not work so use the below cmnd
> nmap -sn -PE <ip> --send-ip
```

### Most prefered nmap scans
```bash
> nmap -sn -v -T4 <ip>

> nmap -sn -PS22,25,80,445,3389,8080 -T4 1<ip> # (most imp)
# UDP -PU
> nmap -sn -PS22,25,80,445,3389,8080 -PU137,138 -T4 <ip> # (most imp)

# sending all pkt in with one cmd
> nmap -PE -PS -PA 192.168.1.0/24 # on defualt ports
> nmap -PE -PS80 -PA80 192.168.1.0/24 # on specific ports
> nmap -PE -PS80,443 -PA22,25 192.168.1.0/24 # on multiple ports

########
- `-PE` sends ICMP Echo Requests to check if hosts are reachable.
- `-PS` sends TCP SYN packets to the default ports.
- `-PA` sends TCP ACK packets to the default ports.
- `192.168.1.0/24` specifies the target subnet.
```

## Service Version & OS Detection
```bash
> nmap -T4 -sS -p- <ip>
# we will not always find common sercvice running on the ports so
PORT       STATE  SERVICE
6421/tcp   open   nim-wan
41288/tcp  open   "unknown"
55413/tcp  open   "unknown"

######## SERVICE DETECTION ############
# -sV will acurately tell the service version runng on the port
> nmap -T4 -sS -sV -p- <ip> 

PORT	    STATE SERVICE	  VERSION
6421/tcp	mongodb open	  MongoDB 2.6.10
41288/tcp	memcached open	  Memcached
55413/tcp	open              vsftd 3.0.3

# if nmap does not detect service version then force the nmap to guess the version
> nmap -T4 -sV -sS --version-intensity -O -p- <ip>

######## OS DETECTION ############
> nmap -T4 -sV -sS -O -p- <ip>

# if nmap does not detect OS then force the nmap to guess the OS
> nmap -T4 -sV -sS -O --osscan-guess -p- <ip>


######################### FINAL #####################################
> nmap -T4 -sV -sS --version-intensity -O --osscan-guess -p- 192.31.214.3
```

## Nmap Scripting Engine (NSE)
```bash
# can be found on 
>  ls -la /usr/share/nmap/scripts

# search for specific scripts
>  ls -la /usr/share/nmap/scripts | grep -e "http"

# Category of scripts
Discovery 
Exploitation
Brute Force 
Safe
##############################################################

> nmap -sS -sV -sC -p- -T4 1<ip> # default script scan -sC

> nmap --script-help=<scriptname> # to check about the particular script

> nmap -sS -sV --script=memcached-info -p- -T4 <ip> #specific script

> nmap -sS -sV --script=memcached-info,ftp-anon -p- -T4 192.224.77.3 #combined script runs

> nmap -sS -sV --script=ftp-* -p- -T4 <ip> # (*) wildcard runs all ftp scripts 

###################### ALL THINGS COMBINED HERE #######################
> nmap -sS -A -p- -T4 <ip> # -A does os,version,script& traceroute scan
```

## Optimizing Nmap Scans
```bash
# --host-timeout
# skip the discovery of host if it does not respond in 5s
> nmap -Pn -sS -F --host-timeout 5s 10.10.23.0/24

# --scan-delay
> nmap -Pn -sS -F --scan-delay 5s <ip>

# -T1(sneaky), -T2 used for IDS evasion 
> nmap -Pn -sS -F -T1 <ip>
```
